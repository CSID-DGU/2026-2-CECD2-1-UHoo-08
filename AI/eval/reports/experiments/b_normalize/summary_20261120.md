## 실험 정보

- 문제: `eval/golden/router/*_v2.jsonl`. 훑어보기는 연습용(dev) 240건을 한 번, 본 측정은 시험용(test) 360건을 세 번 돌렸다. 본 측정 표의 값은 평균 ± 표준편차다

- 방식: 서비스가 쓰는 방식 그대로다(A2, LLM + 구조 규칙). 문제, 프롬프트, 되묻는 규칙은 그대로 두고 Normalize 의 모델만 바꿨다
- 코드: 훑어보기 1a5ae4b, 본 측정 2fd22c7
- 시간: 로컬에서 쟀다. 문제는 하나씩 보냈고, 견주는 모델들을 같은 시간대에 함께 돌렸다. 배포 서버에서 잰 값이 아니다
- 비용: 기록된 토큰 수에 각 회사의 정가를 곱했다. 같은 프롬프트를 되풀이해 보낼 때 받는 캐시 할인은 넣지 않았다

## 읽는 법

- **세 모델의 시나리오 일치율과 값 일치율은 1%p 안이다.** 시나리오 일치율 99.7%, 99.6%, 99.4% 는 314건 중
  한두 문제 차이다. 이 과제에서는 모델을 바꿔도 정확도가 거의 움직이지 않는다. 훑어보기의 일곱 모델도 같았다.
- **차이는 되묻기 판단, 속도, 비용에서 난다.** claude-haiku-5-5 는 쓸데없이 되묻는 일이 가장 적고(정밀도
  88.8%), 되물어야 할 질문은 가장 많이 놓친다(재현율 81.4%). gemini-3.5-flash-lite 는 그 반대다.
- **claude-haiku-5-5 는 가장 빠르고 가장 싸다.** 느린 쪽 값이 1.19초로 지금 모델(3.41초)의 3분의 1 이다.
  답이 늦어지는 일이 드물다는 뜻이다.
- **단가만으로 비용을 견주면 안 된다.** 같은 프롬프트가 claude-haiku-5-5 에서는 3,512토큰, qwen-plus 에서는
  2,444토큰으로 세어진다. 그래도 단가가 낮아 claude-haiku-5-5 의 비용이 지금 모델의 39% 다.
  gemini-3.5-flash-lite 는 입력 단가가 낮지만 출력 단가가 높아 비용이 지금 모델과 같다.
- **claude-haiku-5-5 는 JSON 대신 대화하듯 답하는 일이 있다.** 답의 3.3% 가 그랬고, 360건 중 5건은 다시 물어도
  읽지 못했다. "흠", "몰라", "음"처럼 한두 마디뿐인 말과, 직전 결과를 고치는 "다른 브랜드로" 같은 말이다.
  읽지 못한 질문은 되묻기로 넘어간다. 한두 마디뿐인 말은 되묻는 것이 맞아 손해가 없지만, 조건 수정은
  사용자가 말한 조건이 문장 그대로만 남고 예산이나 특징 같은 값으로는 읽히지 않는다.
- **JSON 응답 옵션을 켜도 양식이 깨질 수 있다.** gemini-3.5-flash-lite 는 값 사이에 코드 조각 같은 글자가 낀
  답을 4번 냈다. 훑어보기에서는 gemini-3.1-pro-preview 가 답을 배열로 감싸 보냈다.
- **같은 질문에 답이 달라지는 정도는 비슷하다.** temperature 를 0 으로 둘 수 있는 것은 qwen-plus 뿐인데,
  반복 일치율은 98.1%, 96.7%, 97.5% 로 큰 차이가 없다.
- **지금 모델의 값은 시나리오 결정 실험의 A2 와 거의 같다.** 같은 문제, 같은 방식이다(시나리오 일치율 99.7%,
  되묻기 재현율 85.3%). 비용만 다르다. 그때는 다른 단가로 계산했다.

## 채택 기준에 따른 판단

시간은 가운데 값으로 견주었다.

| 기준 | 결과 | 판단 |
| --- | --- | --- |
| 정확도가 2%p 이상 높으면 더 비싼 모델로 바꾼다 | 본 측정의 두 후보는 지금 모델보다 비싸지 않다 | 해당 없음 |
| 정확도가 비슷하고(1%p 이내) 비용이나 시간이 절반 이하면 더 싼 모델로 바꾼다: claude-haiku-5-5 | 시나리오 일치율 99.6% 대 99.7%, 값 일치율 99.6% 대 99.4%. 비용 0.42달러 대 1.08달러(39%). 시간 1.00초 대 1.74초(57%) | 충족. 비용이 절반 이하다 |
| 같은 기준: gemini-3.5-flash-lite | 시나리오 일치율 99.4% 대 99.7%, 값 일치율 99.7% 대 99.4%. 비용 1.06달러 대 1.08달러(98%). 시간 1.05초 대 1.74초(60%) | 미충족. 비용도 시간도 절반을 넘는다 |

**채택 기준에 따르면 Normalize 모델은 claude-haiku-5-5 로 바꾸는 쪽이다.** 정확도가 같은 수준이고 비용이
39%, 느린 쪽 시간이 3분의 1 이다.

바꾸기 전에 볼 점이 넷 있다.

- 양식을 못 지키는 답이 3.3% 다. 지금 모델은 0% 다. 조건 수정에서 답을 읽지 못하면 사용자가 말한 조건이
  문장 그대로만 남는다. 아래 다음 조치 2 로 줄일 수 있는지 먼저 확인하는 편이 안전하다.
- 되물어야 할 질문을 지금 모델보다 더 놓친다(재현율 81.4% 대 85.3%). 대신 쓸데없이 되묻는 일은 크게 줄어든다
  (정밀도 88.8% 대 76.7%).
- "만 오천원"을 5,000원으로 읽었다. 한글로 적은 금액은 지금 모델이 더 잘 읽는다.
- 부르는 곳이 DashScope 에서 Anthropic 으로 바뀐다. 서버에 키를 새로 넣어야 하고 요금도 따로 나간다.

gemini-3.5-flash-lite 는 느린 쪽 값(1.37초)만 보면 지금 모델의 40% 지만, 가운데 값과 비용이 기준에 못 미쳐
바꿀 근거가 없다.

- claude-haiku-5-5 가 한 번이라도 끝내 읽지 못한 질문은 8개다. "흠", "몰라", "음", "그냥", "가격은?"은 되묻는 것이 정답이라
  틀린 문제로 잡히지 않았다. "다른 브랜드로", "국내 브랜드로만"은 직전 결과가 있어 조건 수정으로 가지만 값은 읽지 못했다.
  "요즘 많이들 쓰는 파우더 알려줘"는 세 번 중 한 번 읽지 못해 되물었다.

## 한계

- 시험용 문제의 초안과 정답을 Claude 가 만들고 사람이 확인했다. 같은 계열인 claude-haiku-5-5 에 유리했을 수 있다.
  실제 사용자 질문으로 다시 확인해야 한다.
- 시나리오 일치율의 차이(99.7%, 99.6%, 99.4%)는 한두 문제 차이라, 이 값만으로 모델의 우열을 말할 수 없다.
- 시간은 배포 서버가 아니라 로컬에서 쟀다. 모델마다 부르는 곳이 달라 그 차이도 섞여 있다.
- 비용은 정가로 계산했다. 캐시 할인이나 계약에 따라 실제 청구는 달라진다.
- 본 측정에 올리지 않은 네 모델은 연습용으로 한 번 돌린 값뿐이다. gemini-3.8-flash 와
  gemini-3.1-pro-preview 의 시간은 호출 한도에 걸린 값이라 쓸 수 없다.
- 모델마다 temperature 와 생각 기능 설정이 다르다. 설정을 바꾸면 결과가 달라질 수 있다.
- Gemini 는 Vertex AI 로 불렀다. 무료 체험 결제 계정에서는 호출의 열에 하나가 403 으로 거절돼, 정식 계정으로
  바꾼 뒤 다시 돌렸다.

## 다음 조치

1. claude-haiku-5-5 로 바꿀지 정한다. 바꾼다면 서버에 `ANTHROPIC_API_KEY` 와 `LLM_NORMALIZE_MODEL=claude-haiku-5-5` 를 넣고, 배포 서버에서 시간을 다시 잰다.
2. claude-haiku-5-5 가 JSON 으로 답하지 않는 경우를 줄일 방법을 연습용에서 확인한다. 스키마를 함께 보내 양식을 강제하는 방법과, 읽지 못했을 때 양식을 다시 알려 주고 묻는 방법이 있다.
3. "만 오천원"처럼 한글로 적은 금액을 프롬프트의 예시에 더할지 연습용에서 확인한다.
4. Compose 와 Weight 의 모델 비교는 다음 이슈에서 한다. 이번에 만든 후보 목록과 가격표를 그대로 쓴다.
