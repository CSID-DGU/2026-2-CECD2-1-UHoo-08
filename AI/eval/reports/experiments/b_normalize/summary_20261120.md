질문을 검색 조건으로 바꾸는 단계(Normalize)에 쓸 모델을 같은 문제로 견주었다. 모델별 자세한 결과는
같은 폴더의 `<모델>_20261120.md`(시험용 본 측정)와 `<모델>_dev_20261120.md`(연습용 훑어보기)에 있다.
claude-haiku-5-5 를 구조화 출력으로 다시 잰 결과는 `claude-haiku-5-5_schema_20261120.md` 에 있다.

## 실험 정보

- 문제: `eval/golden/router/*_v2.jsonl`. 훑어보기는 연습용(dev) 240건을 한 번, 본 측정은 시험용(test) 360건을 세 번 돌렸다. 본 측정 표의 값은 평균 ± 표준편차다
- 시험용 360건 중 시나리오 정답이 적힌 문제는 314건, 되물어야 하는 문제는 68건이다. 연습용은 각각 208건, 48건이다
- 방식: 서비스가 쓰는 방식 그대로다(A2, LLM + 구조 규칙). 문제, 프롬프트, 되묻는 규칙은 그대로 두고 Normalize 의 모델만 바꿨다
- 코드: 훑어보기 1a5ae4b, 본 측정 2fd22c7, claude-haiku-5-5 를 구조화 출력으로 다시 잰 것 d3687b0
- 시간: 로컬에서 쟀다. 문제는 하나씩 보냈고, 견주는 모델들을 같은 시간대에 함께 돌렸다. 배포 서버에서 잰 값이 아니다. claude-haiku-5-5 를 다시 잰 것만 같은 날 저녁에 따로 돌렸다
- 비용: 기록된 토큰 수에 각 회사의 정가를 곱했다. 같은 프롬프트를 되풀이해 보낼 때 받는 캐시 할인은 넣지 않았다

모델마다 설정이 다른 까닭은 이렇다.

- temperature: Claude 는 이 값을 받지 않는다. Gemini 3 부터는 기본값으로 두라고 안내한다. 0 으로 둔 것은 Qwen 두 모델뿐이다
- 생각 기능: Normalize 는 사용자가 기다리는 첫 단계이고 지금 모델도 생각 없이 답한다. 그래서 끌 수 있는 모델은 끄고, 끌 수 없는 Gemini 는 가장 낮은 단계로 맞췄다. qwen3.8-flash 는 기본으로 켜져 있어 그대로 두면 답 하나에 70초가 걸렸다
- JSON 응답: 모델마다 형식을 강제하는 방식이 다르다. Qwen 은 JSON 모드(`response_format` 의 json_object), Gemini 는 JSON MIME(`response_mime_type`), Claude 는 구조화 출력(답의 스키마)이다. 각 모델이 주는 가장 강한 방식을 썼다. Qwen 과 Gemini 는 답이 JSON 이기만 하면 되지만, Claude 는 칸과 값의 모양까지 스키마로 강제받아 한 단계 더 강하다. Claude 에는 JSON 이기만 하면 되는 옵션이 따로 없다
- Claude 두 모델의 훑어보기와 claude-haiku-5-5 의 첫 본 측정은 스키마를 붙이기 전, 프롬프트로만 양식을 지키게 했을 때의 값이다. claude-haiku-5-5 만 스키마를 붙여 시험용으로 다시 쟀다
- gemini-3.8-flash 의 가격은 2026년 12월 31일까지의 값이다. 2027년 1월 1일부터 두 배가 된다

계획에 있던 후보 중 둘이 바뀌었다. gemini-2.5-flash 는 Vertex AI 에서 지원이 끝나 같은 가격의 후속 모델
gemini-3.5-flash-lite 로 바꿨다. qwen3.8-max 는 게이트웨이 사용 한도로는 본 측정을 할 수 없어 뺐다.

## 읽는 법

- **모델을 바꿔도 시나리오 일치율과 값 일치율은 1%p 안이다.** 시나리오 일치율 99.7%, 99.2%, 99.4% 는 314건 중
  한두 문제 차이다. 이 과제에서는 모델을 바꿔도 정확도가 거의 움직이지 않는다. 훑어보기의 일곱 모델도 같았다.
- **차이는 되묻기 판단, 속도, 비용에서 난다.** claude-haiku-5-5 는 쓸데없이 되묻는 일이 가장 적고(정밀도
  96.0%), 되물어야 할 질문은 가장 많이 놓친다(재현율 81.4%). gemini-3.5-flash-lite 는 그 반대다.
- **스키마를 붙이자 claude-haiku-5-5 의 양식 실패가 없어졌다.** 프롬프트로만 양식을 지키게 했을 때는 답의 3.3% 가
  JSON 대신 대화하듯 온 답이었고, 360건 중 5건은 다시 물어도 읽지 못했다. "흠", "몰라", "음" 같은 한두 마디와
  직전 결과를 고치는 "다른 브랜드로" 같은 말이다. 스키마를 붙인 뒤에는 이런 말에도 빈 칸을 둔 JSON 으로 한 번에
  답했다. 질문당 호출 수가 1.02 에서 1.00 이 됐다.
- **대신 입력 토큰과 비용이 늘었다.** 스키마 설명이 입력에 붙어 질문당 입력이 3,512토큰에서 4,937토큰이 됐고,
  1,000건당 비용이 0.42달러에서 0.56달러가 됐다. 지금 모델의 39% 에서 52% 로 올랐다.
- **QuerySpec 을 그대로 스키마로 넘기면 안 된다.** SDK 는 숫자 범위나 글자 수 제약은 알아서 빼고 보내지만,
  키가 정해지지 않은 `features` 는 빈 객체로만 답할 수 있게 바꿔 보낸다. 그러면 "세미매트 쿠션"에도 특징이
  비어서 온다. 그래서 특징 표의 키 13개를 모두 적은 스키마를 QuerySpec 에서 따로 만들었다. 제목, 설명,
  기본값을 빼서 입력도 줄였다. SDK 가 바꾼 스키마를 그대로 쓰면 입력이 6,036토큰이고, 만든 스키마는 4,943토큰이다.
- **시간은 조금 늘었지만 여전히 지금 모델보다 빠르다.** 가운데 값이 1.00초에서 1.20초가 됐다. 다만 다시 잰 것은
  시간대가 다르다. 같은 시각에 스키마를 붙인 호출과 안 붙인 호출을 번갈아 30건씩 불러 보면 스키마 쪽이 가운데
  값으로 0.07초 느리다. 느린 쪽 값은 1.51초로 지금 모델(3.41초)의 절반이 안 된다.
- **스키마를 붙이자 세트 단계를 더 잘 채운다.** 세트 질문에서 단계를 채운 답이 228개 중 208개에서 224개로 늘었다.
  예산은 있는데 단계가 비어 되묻던 일이 줄어 되묻기 정밀도가 88.8% 에서 96.0% 가 됐다.
- **스키마를 붙이자 묻지 않은 특징을 적는 일이 늘었다.** 답 1,080개 중 31개에서 fragrance_free, waterproof,
  white_cast 를 false 로 적었다(붙이기 전 4개). "여름용 산뜻한 수분크림"에 waterproof false 를 적는 식이다.
  그 카테고리의 특징 표에 없는 키를 적은 답도 3개에서 23개로 늘었다. 스키마에는 특징 키가 카테고리 구분 없이
  한 목록으로 열려 있다. 지금 측정 항목은 특징을 채점하지 않아 위 표에는 드러나지 않는다.
- **단가만으로 비용을 견주면 안 된다.** 같은 프롬프트가 claude-haiku-5-5 에서는 3,512토큰, qwen-plus 에서는
  2,444토큰으로 세어진다. gemini-3.5-flash-lite 는 입력 단가가 낮지만 출력 단가가 높아 비용이 지금 모델과 같다.
- **JSON 으로만 답하게 해도 양식이 깨질 수 있다.** gemini-3.5-flash-lite 는 값 사이에 코드 조각 같은 글자가 낀
  답을 4번 냈다. 훑어보기에서는 gemini-3.1-pro-preview 가 답을 배열로 감싸 보냈다.
- **같은 질문에 답이 달라지는 정도는 비슷하다.** temperature 를 0 으로 둘 수 있는 것은 qwen-plus 뿐인데,
  반복 일치율은 98.1%, 98.1%, 97.5% 로 큰 차이가 없다.
- **지금 모델의 값은 시나리오 결정 실험의 A2 와 거의 같다.** 같은 문제, 같은 방식이다(시나리오 일치율 99.7%,
  되묻기 재현율 85.3%). 비용만 다르다. 그때는 다른 단가로 계산했다.

| 정확도가 비슷하고(1%p 이내) 비용이나 시간이 절반 이하면 더 싼 모델로 바꾼다: claude-haiku-5-5 (구조화 출력) | 시나리오 일치율 99.2% 대 99.7%, 값 일치율 99.8% 대 99.4%. 비용 0.56달러 대 1.08달러(52%). 시간 1.20초 대 1.74초(69%) | 미충족. 비용이 절반을 조금 넘는다 |
| 같은 기준: gemini-3.5-flash-lite | 시나리오 일치율 99.4% 대 99.7%, 값 일치율 99.7% 대 99.4%. 비용 1.06달러 대 1.08달러(98%). 시간 1.05초 대 1.74초(60%) | 미충족. 비용도 시간도 절반을 넘는다 |

**채택 기준에 따르면 지금 모델(qwen-plus)을 유지한다.** claude-haiku-5-5 는 정확도가 같은 수준이지만, 구조화 출력을
붙이면 비용이 지금 모델의 52% 라 "절반 이하"를 2%p 차이로 넘는다.

덧붙일 점이 넷 있다.

- 스키마를 붙이기 전의 값으로는 비용이 39% 라 기준을 채웠다. 그 값은 답의 3.3% 가 양식을 못 지키는 호출로 잰
  것이고, 서비스에서는 그 답마다 한 번 더 묻게 된다. 서비스에 쓸 호출은 스키마를 붙인 쪽이라 그 값으로 판단했다.
- 기준을 넘긴 차이가 작다. 1,000건당 0.02달러, 질문당 입력 220토큰쯤이다. 스키마 설명으로 늘어난 입력이
  호출마다 1,500토큰쯤이므로, 입력을 줄일 방법이 있으면 결과가 바뀔 수 있다.
- 기준에 없는 항목은 claude-haiku-5-5 가 낫다. 되묻기 정밀도가 96.0% 대 76.7% 이고, 느린 쪽 시간이 1.51초 대
  3.41초(44%)다. 반대로 되물어야 할 질문은 더 놓친다(재현율 81.4% 대 85.3%).
- gemini-3.5-flash-lite 는 느린 쪽 값(1.37초)만 보면 지금 모델의 40% 지만, 가운데 값과 비용이 기준에 못 미친다.

## 틀린 문제의 원인

한 번이라도 틀린 문제는 qwen-plus 41건, claude-haiku-5-5 (구조화 출력) 25건, claude-haiku-5-5 (프롬프트로만) 32건,
gemini-3.5-flash-lite 43건이다. 문제 하나가 여러 원인에 들 수 있다.

| 원인 | qwen-plus | claude-haiku-5-5 (구조화 출력) | claude-haiku-5-5 (프롬프트로만) | gemini-3.5-flash-lite | 예 |
| --- | ---: | ---: | ---: | ---: | --- |
| 예산은 있는데 세트 단계가 비어 되물었다 | 18 | 3 | 9 | 24 | "6만원으로 저녁 스킨케어 루틴". 정답 기준과 지금 계약이 달라 생긴다. claude-haiku-5-5 는 단계를 스스로 채워 덜 걸린다 |
| 되물어야 하는데 놓쳤다 | 11 | 14 | 15 | 12 | "지난주에 산 거 계속 써도 돼?", "무난한 거", "하나 골라줘" |
| 요청 종류만 틀렸다 (시나리오는 맞다) | 8 | 5 | 5 | 3 | "좀 더 순한 클렌징폼으로 추천"을 조건 수정으로 읽었다 |
| 값을 틀렸다 | 3 | 1 | 2 | 3 | 아이크림의 카테고리, "만 오천원", "블러셔랑 쉐딩"의 카테고리 |
| 시나리오를 틀렸다 | 1 | 3 | 2 | 3 | "지성한테 젤크림 어때?"를 평가로 읽었다 |

- "지성한테 젤크림 어때?"는 qwen-plus, gemini-3.5-flash-lite, claude-haiku-5-5 (구조화 출력)가 세 번 모두 평가로 읽었다.
  프롬프트로만 잰 claude-haiku-5-5 만 검색으로 읽었다.
- claude-haiku-5-5 는 "아넷사 퍼펙트 UV 같은 선크림 국산으로 없어?"를 두 측정 모두 검색으로 읽었다(세 번 중 세 번, 두 번).
  특정 제품과 비슷한 것을 찾는 요청은 평가로 보내야 한다. "만 오천원 넘지 않는 클렌징밤"의 예산도 두 측정 모두 5,000원으로 읽었다.
- 프롬프트로만 잰 claude-haiku-5-5 가 한 번이라도 끝내 읽지 못한 질문은 8개였다. "흠", "몰라", "음", "그냥", "가격은?"은
  되묻는 것이 정답이라 틀린 문제로 잡히지 않았다. "다른 브랜드로", "국내 브랜드로만"은 직전 결과가 있어 조건 수정으로 가지만
  값은 읽지 못했다. "요즘 많이들 쓰는 파우더 알려줘"는 세 번 중 한 번 읽지 못해 되물었다. 스키마를 붙인 뒤에는 모두 한 번에 읽었다.

## 한계

- 시험용 문제의 초안과 정답을 Claude 가 만들고 사람이 확인했다. 같은 계열인 claude-haiku-5-5 에 유리했을 수 있다.
  실제 사용자 질문으로 다시 확인해야 한다.
- 시나리오 일치율의 차이(99.7%, 99.2%, 99.4%)는 한두 문제 차이라, 이 값만으로 모델의 우열을 말할 수 없다.
- 시간은 배포 서버가 아니라 로컬에서 쟀다. 모델마다 부르는 곳이 달라 그 차이도 섞여 있다.
- claude-haiku-5-5 를 구조화 출력으로 다시 잰 값은 다른 모델과 잰 시간대가 다르다. 다른 모델은 다시 재지 않았다.
- Claude 만 답의 스키마까지 강제받았다. Qwen 과 Gemini 는 JSON 이기만 하면 되는 방식으로 쟀다.
- 측정 항목은 특징(features)을 채점하지 않는다. 스키마를 붙인 뒤 묻지 않은 특징을 적는 일이 늘었지만 수치에는 드러나지 않는다.
- 비용은 정가로 계산했다. 캐시 할인이나 계약에 따라 실제 청구는 달라진다.
- 본 측정에 올리지 않은 네 모델은 연습용으로 한 번 돌린 값뿐이다. gemini-3.8-flash 와
  gemini-3.1-pro-preview 의 시간은 호출 한도에 걸린 값이라 쓸 수 없다.
- 모델마다 temperature 와 생각 기능 설정이 다르다. 설정을 바꾸면 결과가 달라질 수 있다.
- Gemini 는 Vertex AI 로 불렀다. 무료 체험 결제 계정에서는 호출의 열에 하나가 403 으로 거절돼, 정식 계정으로
  바꾼 뒤 다시 돌렸다.

## 다음 조치

1. 채택 기준대로 Normalize 모델은 지금 모델을 유지한다. claude-haiku-5-5 를 다시 검토하려면 스키마 때문에 늘어난 입력을 줄일 방법부터 찾는다.
2. 스키마를 붙였을 때 묻지 않은 특징을 적는 일을 줄인다. 카테고리의 특징 표에 없는 키는 Normalize 에서 버리는 방법과, 묻지 않은 참거짓 값은 적지 않도록 프롬프트를 보완하는 방법을 연습용에서 확인한다.
3. 특징을 채점할 수 있게 골든셋에 특징 정답을 더한다. 지금은 특징이 잘못 들어가도 수치로 알 수 없다.
4. "만 오천원"처럼 한글로 적은 금액을 프롬프트의 예시에 더할지 연습용에서 확인한다.
5. Compose 와 Weight 의 모델 비교는 다음 이슈에서 한다. 이번에 만든 후보 목록과 가격표를 그대로 쓴다.
