# 라우터 골든셋 생성 (v2)

`eval/golden/router/*_v2.jsonl` 600건을 만들 때 쓴 지시와 정답 기준이다.
v1 파일은 그대로 두고, v2 는 새 파일로 따로 만들었다.

## 왜 다시 만들었나

- v1 은 되묻는 것이 정답인 시험용 문제가 3건뿐이라, 되묻기 판단이 잘 되는지 잴 수 없었다.
- v1 의 시험용 문제를 보고 프롬프트와 라우터를 고쳤다. 같은 문제로 다시 재면
  실력이 아니라 문제를 외운 결과가 된다. 고친 효과는 새 문제로 잰다.
- 요청 종류를 헷갈리기 쉬운 표현을 따로 모아, 어디서 틀리는지 볼 수 있게 했다.

## 구성

처음 300건을 만든 뒤, 같은 구성으로 300건을 더 만들어 두 배로 늘렸다.
처음 300건으로는 LLM 조건의 시나리오 일치율이 모두 100% 에 가까워 조건끼리 차이를 볼 수 없었기 때문이다.
처음 파일은 그대로 두고, 더한 문제는 `*_add_v2.jsonl` 에 따로 두었다.

| 내용 | 처음 파일 | 더한 파일 | 시험용 | 연습용 |
| --- | --- | --- | ---: | ---: |
| 검색 | `s2_search_v2.jsonl` | `s2_search_add_v2.jsonl` | 60 | 40 |
| 평가 | `s1_evaluate_v2.jsonl` | `s1_evaluate_add_v2.jsonl` | 60 | 40 |
| 세트 | `s6_bundle_v2.jsonl` | `s6_bundle_add_v2.jsonl` | 60 | 40 |
| 조건 수정 (직전 결과 있음) | `s7_refine_v2.jsonl` | `s7_refine_add_v2.jsonl` | 20 | 14 |
| 막연한 질문 | `ambiguous_v2.jsonl` | `ambiguous_add_v2.jsonl` | 60 | 40 |
| 헷갈리기 쉬운 표현 | `confusing_v2.jsonl` | `confusing_add_v2.jsonl` | 100 | 66 |
| 합계 | | | 360 | 240 |

조건 수정은 직전 결과가 있는지만으로 정해지므로 적게 두었다.

id 는 v1 과 겹치지 않게 1000번대와 2000번대를 쓴다. 처음 파일은 검색 1001, 평가 1101, 세트 1201,
조건 수정 1301, 막연한 질문 1401, 헷갈리기 쉬운 표현 1501 부터이고, 더한 파일은 각각 1000 을 더한
2001, 2101, 2201, 2301, 2401, 2501 부터다.

## 만든 방식

Claude 에게 아래 지시를 주어 초안을 만들고, 사람이 정답을 하나씩 확인했다.
v1 에 있는 질문, Normalize 프롬프트의 예시에 쓰인 제품 이름은 쓰지 않았다.

더한 300건은 같은 지시에 아래를 덧붙여 만들었다. 띄어쓰기와 문장 부호를 뺀 글자가 v1, v2 의
어느 질문과도 같지 않은지 스크립트로 확인했다.

```
이미 있는 v1, v2 질의와 같은 문장을 쓰지 마라. 평가 질의의 제품도 되도록 새 제품으로 써라.
실제 검색창에서 보이는 표현을 조금씩 섞어라.
- 줄임말과 신조어 ("수부지", "ㅊㅊ", "올영", "듀프", "저렴이")
- 금액을 적는 여러 방법 ("십만원", "100,000원", "25000원", "만 오천원", "9만 원")
- 두 제품을 "vs" 로 견주는 말
- 사정을 길게 풀어 쓴 말 ("이사하면서 화장품 다 버렸는데 8만원으로 기초 한꺼번에 사려고")
```

## 지시

```
화장품 추천 서비스의 검색창에 들어올 법한 한국어 질의를 만들어라.
실제 사람이 검색창에 칠 법한 길이와 말투로 쓴다. 문어체 금지.
같은 문형을 반복하지 마라. 기존 v1 질의와 같은 문장을 쓰지 마라.

1. 검색 50개. 조건으로 제품을 찾는 질의.
   카테고리 여섯 개(base, sun, lip, skincare, eye, cheek)를 섞는다.
   예산을 말하는 것, 날씨나 환경을 근거로 드는 것, 가성비를 묻는 것,
   기준이 본인이 아닌 것(인기, 다른 사람)을 조금씩 넣는다.

2. 평가 50개. 실제로 있는 특정 제품 하나가 어떤지 묻는 질의.
   "어때?" 한 가지 문형만 쓰지 말고, 피부 타입, 지속력, 자극처럼
   구체적으로 묻는 것을 섞는다.

3. 세트 50개. 전체 예산을 말하고 여러 단계를 묶어 달라는 질의.
   단계 이름을 말하는 것과 "스킨케어 세트"처럼 묶어 말하는 것을 섞는다.

4. 조건 수정 17개. 방금 받은 결과에 조건을 더하거나 바꾸는 질의.
   그중 일부는 말투만 보면 새 검색, 평가, 세트로 읽히는 질의로 만든다.

5. 막연한 질문 50개. 그대로는 추천할 수 없어 되물어야 하는 질의.
   - 조건이 하나도 없는 것
   - 평가를 원하지만 어떤 제품인지 알 수 없는 것 ("이거", "그 제품")
   - 세트를 원하지만 예산이 없는 것
   - 말이 끊기거나 뜻을 알 수 없는 것

6. 헷갈리기 쉬운 표현 83개. 겉모습과 요청 종류가 어긋나는 질의.
   - 특정 제품을 대신할 것, 비슷한 것을 찾는다 (평가)
   - 두 제품을 견준다 (평가)
   - 제품 이름에 "세트"가 들어간다 (평가)
   - 종류만 말하고 어떠냐고 묻는다 (검색)
   - 브랜드만 말한다 (검색)
   - 조건 수정 말투지만 직전 결과가 없다 (검색)
   - 금액은 있지만 제품 하나다 (검색)
   - "세트"라는 말이 있지만 세트를 짜 달라는 게 아니다 (검색)
   - "세트"라는 말은 없지만 여러 개를 예산에 맞춘다 (세트)
   - 조건과 함께 특정 제품을 묻는다 (평가)
   - 계절을 조건으로 쓴다 (환경 근거가 아니다)

질의마다 정답 시나리오, 요청 종류, 되물어야 하는지를 함께 적어라.
사람이 봐도 갈릴 것 같으면 그 항목은 비워 두어라.
```

## 정답을 적은 기준

- **되물어야 하는지는 거의 모든 문제에 적었다.** 되묻기 정밀도와 재현율을 재려면
  되묻지 않는 것이 정답인 문제도 필요하다.
- 되묻는 것이 정답인 경우는 세 가지다.
  1. 평가를 원하는데 어떤 제품인지 알 수 없다.
  2. 세트를 원하는데 전체 예산이 없다.
  3. 카테고리, 특징, 조건, 예산, 기준 제품이 하나도 없다.
- 전체 예산이 있고 카테고리나 단계를 말한 세트는 되묻지 않는 것으로 보았다.
- 막연한 질문은 시나리오가 사람이 봐도 갈리면 적지 않았다. 되물어야 한다는 것만 채점한다.
- 직전 결과가 있는 질문은 말투와 상관없이 조건 수정이 정답이다. 말투가 조건 수정이
  아닌 문제는 요청 종류를 적지 않았다. LLM 이 무엇으로 읽든 경로는 같기 때문이다.
- 기준 상품은 있는지만 본다. 표현이 모델마다 달라 문자열을 맞추게 하면
  같은 제품을 다르게 적은 것이 오답이 된다.
- 예산은 "3만원 이하"처럼 숫자가 분명한 것만 적었다. "1만원대"는 적지 않았다.
- 카테고리는 한 카테고리로 분명히 정해지는 문제에만 적었다.

## 태그

- `ambiguous`: 되물어야 하는 질문
- `confusing`: 헷갈리기 쉬운 표현
- `value`, `env`, `target`, `exclude`: v1 과 같은 뜻

## split

시험용(test)은 리포트 수치를 낼 때만 쓴다. 프롬프트와 기준값은 연습용(dev)만
보고 고친다. 한번 시험용으로 정한 문제는 연습용으로 바꾸지 않는다.
