# 라우터 골든셋 생성 (v1)

`eval/golden/router/*.jsonl` 128건을 만들 때 쓴 지시다.
"합성 데이터를 어떻게 만들었는지" 확인할 때 사용한다.

## 만든 방식

Claude 에게 아래 지시를 주고, 나온 질의를 사람이 훑어 걸렀다. 실제 사용자가
쓸 법하지 않은 문장(예: "본 제품의 적합도를 평가해 주십시오")은 뺐다.

## 지시

```
화장품 추천 서비스의 검색창에 들어올 법한 한국어 질의를 만들어라.
네 가지 요청 유형이 고르게 나와야 한다.

  SEARCH    조건으로 찾아 달라           "여름에 안 무너지는 쿠션"
  EVALUATE  특정 상품이 어떤지 묻는다     "라네즈 네오쿠션 어때?"
  BUNDLE    예산 안에서 여러 단계를 묶는다 "10만원으로 스킨케어 세트"
  REFINE    방금 결과에 조건을 더한다      "더 저렴한 걸로"

유형마다 30개 이상. 그중 20%는 무엇을 원하는지 분명하지 않은 질의로 만든다.
되물어야 하는 상황을 재기 위해서다. "추천해줘", "다시", "그거 어때?" 처럼
짧고 맥락이 빠진 말이 여기 해당한다.

다음을 고르게 섞어라.
- 카테고리 네 개 (base, sun, lip, skincare)
- 예산을 말하는 것과 말하지 않는 것
- "요즘 날씨", "미세먼지" 처럼 환경을 근거로 드는 것
- "가성비", "저렴하면서 좋은" 처럼 가격 대비 가치를 묻는 것
- "요즘 인기 있는", "친구한테 어울릴" 처럼 기준이 본인이 아닌 것

실제 사람이 검색창에 칠 법한 길이와 말투로 쓴다. 문어체 금지.
같은 문형을 반복하지 마라.
```

## 기대값을 적은 기준

- **적은 키만 적는다.** 모든 필드를 고정하면 프롬프트를 조금 고쳐도 골든셋이
  통째로 깨져, 나아졌는지가 아니라 "또 깨졌다"만 남는다.
- 기준 상품은 **있는지만** 본다. 표현이 모델마다 달라 문자열을 맞추게 하면
  "라네즈 네오쿠션 21호"와 "네오쿠션 21호"가 오답이 된다.
- 모호한 질의는 대개 `needs_clarification` 하나만 적는다. 어디로 갈지는
  사람이 봐도 갈리는 것이라, 시나리오까지 고정하면 정답이 임의가 된다.
- 조건 수정 질의는 입력에 `parent_job_id` 를 넣는다. 직전 job 이 없으면
  라우터가 새 검색으로 내리도록 만들어 두었기 때문이다.

## split

각 골든셋 항목에 `dev` 또는 `test`를 명시적으로 지정한다.

`dev`는 프롬프트를 개발하고 수정할 때 사용하는 데이터이고,
`test`는 최종 성능을 측정할 때 사용하는 데이터다.

한번 `test`로 지정한 항목은 이후 새로운 질의를 추가해도
`dev`로 변경하지 않는다. 그래야 이전 리포트와 이후 리포트의
test 성능을 같은 테스트셋 기준으로 비교할 수 있다.

새로운 질의를 추가할 때는 기본적으로 `dev`에 넣어 개발에 사용하고,
충분히 검증된 뒤 별도의 절차를 거쳐 test에 편입한다.
