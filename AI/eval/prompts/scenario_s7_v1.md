# 조건 수정 골든셋 생성 기록

`eval/golden/scenario/s7_refine_v1.jsonl`(20건)을 만든 방법이다. Claude Code 가 아래 지시를 받아,
`personas_v1` 과 읽기 전용으로 조회한 상품 가격, 제품 종류로 만들었다.

## 지시

```
personas_v1 의 20명마다 조건 수정(S7_REFINE) 레코드를 하나씩 만든다.

- input.parent 에 이전 검색의 원문과 질의 해석을 적는다. 러너가 이것을 먼저 돌려
  이전 job 으로 쓴다
- input.refine_presets 에 고른 선택지 키를, input.raw_query 에 BE 가 보내는 모양
  (선택지 문장 뒤에 직접 쓴 문장을 쉼표로 이은 것)을 적는다
- 종류를 tags 첫 항목에 적는다
  cheaper  예산이 있는 검색에서 더 저렴하게 8건
  preset   더 저렴하게가 아닌 선택지 6건
  mixed    선택지 여럿, 또는 선택지와 직접 쓴 문장 3건
  text     직접 쓴 문장만 3건. 카테고리와 제품 종류는 바꾸지 않는 문장으로
- 기대 성질
  - 보유 제품은 결과에 없다(must_exclude)
  - 상위 5개는 이전 검색의 카테고리, 제품 종류를 지킨다. 예산이 있으면 예산 상한도
    지킨다. 더 저렴하게를 골랐으면 상한은 이전 상한 × 0.8 을 천 원 단위로 내린 값이다
  - 결과가 비어 있지 않다
  - 모든 결과 카드에 순위 변화가 있다(change_present)
- split 은 페르소나의 split 을 따른다
```

## 정한 것과 그 이유

- **조건을 만족하는 상품이 5개 이상인 질의만 썼다.** 상품 마스터에서 카테고리, 제품 종류,
  예산 상한, 보유 제품 제외를 모두 지키는 상품 수를 세어 확인했다. 그래서 3만원 쿠션이 아니라
  4만원 쿠션처럼 예산을 정했다(3만원에서 더 저렴하게면 2.4만원 이하 쿠션이 5개뿐이다).
- **이전 검색의 결과는 적지 않았다.** 러너가 그때그때 이전 검색을 돌린다. 순위 변화는 이전
  결과에 따라 달라지므로 NEW, UP 같은 값은 기대하지 않고, 값이 실렸는지만 본다.
- **직접 쓴 문장은 질의 해석 LLM 을 거친다.** text, mixed 의 직접 쓴 문장이 카테고리를 바꾸게
  해석되면 top5_all 이 실패한다. 그때는 해석 쪽 문제로 본다.
